uses to audit Digby's own framework. Everything here is deployed to `/opt/crossmodel/scripts/framework-audit`
on every wave, so a probe added in the repo is on the boxes after the next deploy.

Probes print one JSON object (BigInt → Number) and exit 0; SSM caps stdout at ~24 KB, so keep sections `LIMIT`ed.
**Output paging (2026-09-23):** `run-on-box.sh` fetches results in `ROB_CHUNK`-byte pages (box-side temp files + `tail -c +N | head -c C` byte ranges), so a probe printing more than the ~24 KB `GetCommandInvocation` cap comes back COMPLETE, not cut mid-JSON — `audit-live-state.js` (~29 KB) is the canonical case. Knobs: `ROB_CHUNK` (default 20000), `ROB_RANGE=from[:to]` (print one 1-based byte window), `ROB_PAGING_DISABLED=1` (legacy verbatim single-shot). For anything larger still, redirect to a local file and slice that.
Probe SQL idioms: uuid columns compare as `id::text LIKE 'abcd1234%'`; `hook_events` joins `event_hooks h ON h.id=e."hookId"`
(the target is `h."targetChatId"`); `pending_chat_messages."chatId"`; `activities.metadata->>'chatId'`.
**Redis from a prodq probe (2026-09-26):** require packages by ABSOLUTE path (`/app/node_modules/redis`) — prodq copies the probe to `/tmp` inside the container and a bare require cannot resolve there; and build your own client from `process.env.REDIS_URL`, never `require('/app/dist/config/redis')` — the app singleton's winston console transport prints `✅ Redis connected` to stdout and corrupts the probe's pure-JSON output. `run_lock_paired_now` in `audit-live-state.js` is the canonical shape (SCAN, both-reads-matched by sessionId — a lock count and a DB row count taken as separate SSM calls straddle run churn and read like a leak).

## `backtest-auto-route.js` — the patience-plan §4.5 replay (one-shot `AR0926-REPLAY`)

What it is: `docs/PATIENCE_AUTO_ONLY_DEPRECATION_PLAN_2026-09-25.md` §4.5 — the in-place back-test of the Auto router.
It selects the last `<days>` of HUMAN, non-supervisor turns (chats `isSupervisor=false`, `isProjectSupervisor=false`,
`parentChatId IS NULL`, owner not a child; user rows whose next row is an `engine='agent'` assistant row with no
`metadata.origin`), re-runs the compiled heuristic (`/app/dist/.../platform/auto-router`) and asks the decision gate
(`decide()` with the SAME `autoRouteState` / `autoRouteQuestions` builders production uses, `spec` pinned, 200 ms floor,
serial) and prints ONLY aggregates: counts per segment, U × H / U × gate@τ / H × gate@τ confusion matrices, coverage at the
act thresholds (0.7 / 0.85 for deep_research), top-label ECE + Brier, L3 rates, over/under-escalation with Wilson 95 %
bounds + a user-clustered bootstrap, the McNemar-style paired (gate − heuristic) bound, T / $ / thumbs-down per level,
decision error rate + latency p50/p95, the shift metric, distinct users per class, min/max createdAt and the
"verdict vs §4.6" table (pass / fail / n/a with the sample rule). Never a message, never a user id.

Facts to honour:
- **Egress rule (owner Q1):** `<spec>` is `deepseek-flash` until the owner approves TypeSafe egress for non-Auto sends;
  `jev` after. Each scored message is one call to that backend — a 30-day window at ~40 human sends/day is ≈1,200 calls.
- **Telemetry is stubbed** (`recordLoopMetric` / `recordLoopMetrics` overwritten on the loop-metrics namespace before the
  first `decide()`; sessions tagged `backtest:<runId>`). The report's `aux.telemetryGuestDecisions.backtestLeakRows` must
  read 0 and `telemetry.stubbedRows` ≥ the number of decide calls — otherwise the stub did not take.
- **The container filesystem is ephemeral.** The batch jsonl + cursor live INSIDE the active backend container at
  `/var/tmp/ar-backtest/<runId>.jsonl` / `.cursor.json` (override with `--out-dir`). A blue-green flip mid-run loses them
  (the next invocation restarts the run with a fresh salt). `docker cp` the directory out when the loop finishes.
- **Guests are unmeasurable here:** anonymous turns are never persisted as `crossmodel_messages` rows (Redis 24 h
  sessions); the guest count comes from live `decision_gate` rows only (`"sessionId" IS NULL`).
- **U is weak:** `metadata.mode` on rows without `routing` is the chat's stored level at send time (restore-contaminated
  unless `routingSource='user_picked'`); every U-based verdict says so. The label-window `user_picked` rows (§4.2) are the
  real bar — this replay is the §4.3 substitute while volume is short.
- Runs ≤ `<batch>` (default 300) messages per invocation and continues from the cursor file, so ONE invocation is
  ~60–90 s at the 200 ms floor. Run the loop DETACHED (`systemd-run --collect`): the ec2-ops CI ssh session broken-pipes
  on long-silent streams, and `run-on-box.sh` caps a command at the SSM window.

Local proof (no network): `node scripts/framework-audit/backtest-auto-route.js --dry-run` (synthetic corpus, stubbed Prisma +
decide) and `bash scripts/framework-audit/backtest-auto-route.test.sh`; the pure metric functions are pinned by
`backend/src/scripts/backtest-auto-route-metrics.test.ts`.

## `backtest-agent-decisions.js` — the agent-decisions replay (one-shot `AD0927-REPLAY`)
